# ADR 0000: ドキュメンテーション方針

## Status

Accepted (2026-07-25)

## Context

恒久文書は、書かれた経緯(会話・調査・作業ログ)が失われた後に、経緯を
知らない読者が読む。また文書群には依存関係があり、無秩序な相互参照は
どちらの文書も単体で読めなくする。本プロジェクトは英語・日本語の二言語で
文書を提供するため、言語間の同期も規律が要る。

## Decision

### 1. 層と参照方向

文書を2層に分ける。

- **生きたドキュメント**(README、CONTRIBUTING、ROADMAP、ソースコードと
  docstring): 常に「今の姿」を現在形で語り、編集されて進化する。
  単体で自己完結し、現在の仕様の理解に他文書への参照を必要としない。
- **ジャーナル**(ADR、調査記録 docs/CONCLUSION.md、リリースノート、
  commit): 記録された時点の内容で凍結される。

参照は**ジャーナル → 生きたドキュメントの一方向のみ**。生きたドキュメント
に「ADR NNNN 参照」「調査記録参照」を書かない。決定の「結果」(現在の
挙動・仕様)は生きたドキュメント本文に平文で書き、「なぜか」はジャーナル
側が対象ファイル・箇所を名指しして記録する。Why への導線は ADR index
(このディレクトリの README)が持つ。

### 2. ADR の範囲

ADR は**現状の実装を説明する判断**のみを置く。変更は新しい ADR で
supersede する。対象が実装から消えた ADR は削除する — 変更履歴は git が
持ち、ADR 群は履歴ではなく現在の設計の Why の一覧である。

### 3. 自己完結

成果物(文書・commit message・PR)に、その成果物の中で定義されていない
ラベル・略称・「前述の件」を持ち込まない。単体で「何が・なぜ」が読める
ことを提出前に確認する。

### 4. 二言語運用

- README(ルート `.md` / `docs/README.jp.md`)と ROADMAP は両言語を
  同時に更新する。CI の tandem チェックが強制する。
- ADR は日本語を正典とし、英語版(`NNNN-slug.md`)は任意で後追いする。
  対の無い単言語文書は tandem チェックの対象外。

## Consequences

- 読者は README だけで現在の仕様に到達でき、Why が要るときだけ ADR index
  経由で掘れる。
- ADR の削除・supersede が生きたドキュメントの編集を要求しない(逆参照が
  無いため)。
- 二言語の片側だけ更新した push は CI で失敗する。
